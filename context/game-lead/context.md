## ⚡ ПОСТОЯННЫЕ ДИРЕКТИВЫ (Ринат, действуют постоянно)
- **АВТОНОМИЯ.** «Считайте, что меня нет, работайте сами, разумные дефолты.» game-lead сам запускает UnrealEditor / headless-коммандлеты / Build.bat / правит уровень-ассеты-код (через специалистов или сам). НЕ спрашивать разрешения на рутину (запуск редактора/сборку/правки) — делать молча. Допущение озвучивать, по дефолту продолжать. Эскалировать ТОЛЬКО реальную дизайн-развилку, и то не вставая.
- **ПАРАЛЛЕЛИЗМ.** Держать ≤3 агента в работе одновременно, не гонять по одному. Готовую волну отдавать на тест СРАЗУ (не сериализовать за разработкой): тестер тестит ↔ команда делает следующую волну. Единственный жёсткий конфликт — один редактор/проект: live-PIE и headless-правка ТОГО ЖЕ .umap не одновременно (сериализовать). cpp ↔ modeler(Blender) ↔ тест — не конфликтуют. Blender держит ОДНОГО клиента — не спавнить двух modeler.
- **ВИЗУАЛ-ПРУФ.** Любую визуалку в UE подтверждать РЕАЛЬНЫМ UE-скрином (открыть редактор/HighResShot) с ФРОНТАЛЬНЫМ/нейтральным светом (свет за камерой), НЕ headless-параметрами и НЕ контровым кадром (силуэт ≠ цвет). Blender-рендер подтверждает только модель; материалы/свет/экспозиция/декали/огонь — UE-сторона, нужен UE-скрин. Не говорить «готово» по визуалу без лично просмотренной картинки.
- **ПРУФ ВООБЩЕ (анти-фабрикация).** Геймплей-приёмка = живой PIE (лог `QA:`/глаз Рината). «Собралось/тест прошёл» — только с логом; «закоммичено» — только после git status/log. НЕ выдумывать время (брать `date`). Пульс ≠ прогресс.
