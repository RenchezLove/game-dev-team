Исходники в UTF-8 БЕЗ метки порядка байтов — сборщик передаёт компилятору `/utf-8` (`VCToolChain.cs:516`), русские литералы работают.
- **Не коммитить ассеты оператора** (BP_*.uasset, *.umap) — только свои Source/ (+Config, если правил сам). Фича-ветки, master и слияния не трогаю. Новые параметры — EditAnywhere+BlueprintReadWrite+DisplayPriority (директива Рината 06-25).
- **UMG из чистого C++ (этап F)**: дерево в NativeOnInitialized (WidgetTree->ConstructWidget, RootWidget=CanvasPanel), CreateWidget<T>(PC, T::StaticClass()) без BP-наследника. Модули: UMG (public) + Slate/SlateCore (private). У UButton 5.5 НЕТ SetPadding — размер кнопки под палец задавать USizeBox.
- **Плагин GameAnalytics подключён УСЛОВНО** в Build.cs: `WITH_GAMEANALYTICS=1` только если есть `Plugins/GameAnalytics/GameAnalytics.uplugin` — копия без плагина остаётся собираемой. Ключи теперь вшиваются отдельным блоком того же файла (см. СЕЙЧАС).
- **Тесты**: `CombatTestWorld::TickWorld` (++GFrameCounter перед World->Tick) обязателен для тиков в однокадровом RunTest; фон C4459 ×12 и 2 предупреждения C4996 плагина аналитики — пре-существующие, не блокируют. Свои тесты — всегда в НОВЫЙ файл (иначе гонка с чужими правками).
- **Подсистему объекта игры в тесте создавать только с хозяином-`UGameInstance`:** у `UGameInstanceSubsystem` задан `ClassWithin`, и `NewObject<T>()` без хозяина валит тест жалобой «created in invalid Outer». Правильно: `NewObject<UGameInstance>(GetTransientPackage())`, затем `NewObject<T>(GI)`.
- **`UGameMapsSettings` требует явной строки `EngineSettings` в `PrivateDependencyModuleNames`**, хотя `Engine` тянет этот модуль публично: без неё LNK2019 на этапе компоновки.
- **Имена UENUM глобальны для всего движка** (UHT: «shares engine name»): `EGraphicsPreset` уже занят `HardwareTargetingSettings.h` — свои перечисления называть с приставкой проекта (`EContraryGraphicsPreset`). Ловится только сборкой, редактор об этом не предупреждает.
- **`FText::AsNumber` РАЗБИВАЕТ разряды по локали** (1120 → «1 120»): для пикселей/версий/идентификаторов передавать `&FNumberFormattingOptions::DefaultNoGrouping()`.
- **GConfig не умеет писать в ПРОИЗВОЛЬНЫЙ ini-файл**: `SetString` молча выходит, если файла нет в кеше (`FConfigCacheIni::Find` подгружает только существующий файл и ставит ему `NoSave=true`). Поэтому «сохранение настроек» в headless-тесте проверяется не записью файла, а чтением подготовленного файла + проверкой флага `CPF_Config` у полей. Боевой `GameUserSettings.ini` разработчика тесты трогать НЕ должны: `UGameUserSettings::SaveSettings()` вдобавок пишет `Scalability::SaveState` в `EditorSettings.ini` — то есть в настройки редактора Рината.

## Решения
- Health: игрок И враги — через `UStatsComponent` (TakeDamage БЕЗ Super). `HandleDeath()` virtual; `ReloadCurrentWeapon` virtual (патроны из рюкзака, AAmmoItem-стак).
- `GetMesh()==HeadMesh==Leader` модульного гуманоида; Torso/Legs — followers (SetLeaderPoseComponent). Оружие к кости `R_Hand`, офсеты — параметры.
- Волк — НЕ гуманоид: ACharacter + SK_Wolf + Single Node анимации; ИИ = AWolfAIController(AEnemyAIController).
- **SetFocus сам пешку НЕ вращает** (UE 5.5 Pawn.cpp:1049) — доворот наш StartAimTurnTo.
- ИИ погони: состояния Idle/Chase/Attack, навигация с прямым запасным путём; отладочный лог дросселирован.
- **Игровой слот сохранения один (`ContrarySave`), поля удержания в нём же:** `SaveGame()` игрока создаёт свежий объект → ПЕРЕНОСИТ поля удержания из прежнего сейва (`UContrarySaveGame::CopyRetentionData`). Компоненты удержания правят ТОЛЬКО свои поля через `LoadOrCreateSaveObject`/`WriteSaveObject`. Отдельно от него — служебный слот аналитики `ContraryAnalytics` (см. СЕЙЧАС), он переживает «Новую игру».
- Чистая логика серии ежедневных входов — `Retention/DailyRewardLogic.h` (без UObject) — гоняется автотестом без редактора.
- **АРХИТЕКТУРНОЕ РЕШЕНИЕ (моя поправка к решению лида):** переводимое имя предмета живёт НА ЭКЗЕМПЛЯРЕ (`AMasterInventoryItem::ItemDisplayText` + `GetItemDisplayText()` с откатом название→ключ→заглушка), а НЕ на классе: один класс обслуживает разные предметы (`AQuestItem` — и шкура, и ноутбук; `AConsumableItem` — вода/консервы/бинт).
- **⛔ КЛЮЧИ, КОТОРЫЕ НЕЛЬЗЯ ПЕРЕВОДИТЬ (сломает квест):** `AMasterInventoryItem::ItemName`, `FQuest::RequiredItemName`, `FQuest::KillTargetTag`, значения в `ElderNPC.cpp` («Шкура волка», «Ноутбук»), сравнение `QuestComponent.cpp:204,252`.
- **ПАТТЕРН ЛОКАЛИЗАЦИИ (эталон — `UI/PlayerStatsWidget.h`):** `UPROPERTY(EditAnywhere, BlueprintReadWrite) FText` с дефолтом `NSLOCTEXT` ПРЯМО В ЗАГОЛОВКЕ (UHT запрещает LOCTEXT в дефолтах свойств); сборка строки — `FFormatNamedArguments` + `FText::Format`; числа — `FText::AsNumber(FMath::RoundToInt32(...))`. Ловушка `FText::FromString` на потребителе обнуляет перевод.
- **Архитектура ADR-048:** C++ UUserWidget-классы с кубиками `BindWidgetOptional` (пусто → предупреждение, не падение); раскладку WBP строит РИНАТ мышкой; в HUD слоты TSubclassOf: слот пуст → работает старый Canvas-путь, назначен → UMG. Canvas-код панелей НЕ удалять. Модальные окна Z=30, экран смерти Z=35, постоянные панели Z=5.
- **ЛОВУШКА СКРЫТИЯ:** если код прячет кубик со значением, а подпись лежит рядом в дизайнере — подпись остаётся висеть. Решение: привязывать КОНТЕЙНЕР и прятать его (`AmmoRow`).
- **Живой признак платформы (не выдумывать свой):** `AContrarySurvivorPlayerController::HasTouchLayer()` (`.h:115`), под ним `#if PLATFORM_ANDROID`. Отвечает «показан ли слой экранных кнопок», а не «телефон ли это».
- **Android-тапы:** тап НЕ порождает клик мыши для игрового ввода — порождает Touch1..Touch3 (`PlayerInput.cpp:473`). Легаси-действие `ScreenTap` → тот же `Fire()`; позиция тапа = кеш курсора вьюпорта. UMG от пальца работает штатно (`bTouchFallbackToMouse`). `DefaultTouchInterface=None` в DefaultInput.ini.
- **Генератор панелей** `Source/ContrarySurvivorEditor/GenerateWbpCommandlet.cpp` — за мной, но сейчас его правит сосед. Перегенерация только по сигналу лида: с ключом `-force` затрёт стилизацию Рината.

## Ограничения / тех-долги (черновые, на тюнинг и добивку)
- Атака врага без проверки прямой видимости → теоретически удар через тонкую стену в упор.
- Числа баланса черновые: пистолет 25 урона дважды в секунду, нож 35, бандит 80 здоровья, волк 40, предел брони 0.75.
- Навмеш «по приглашению» требует у RecastNavMesh режима `RuntimeGeneration=Dynamic` в уровне.
- Пикап-предмет визуально неотличим от пикапа-денег (заметка по удобству).
- Волк при количестве спавна 0 всё равно спавнится один (`FMath::Max(1, NumToSpawn)`, `MasterEnemyBase.cpp:235,246`) — ждёт решения Рината.
- НЕ ПРОВЕРЕНО живьём (нужен живой запуск или устройство): стик под пальцем, меню паузы на экране, мультитач, стартовый экран Б3 глазами.

## Уроки метода (не повторять промахи)
- **Локализация, урок про поиск:** обход по списку панелей структурно НЕ находит тексты, живущие в игровых классах (так выпали метки над NPC и имя убийцы). Сильнее того — обратная проверка лида: искать слова в СОБРАННОМ файле перевода и смотреть, чего там НЕТ.
- Масштаб задачи заявлять только замером, а не на глаз.
- Проверять сохранения ПЕРЕД тем как называть вопрос блокирующим.
- Искать по ВСЕМУ `Source`, а не по одному модулю.
- Считать длину строки в знаках для телефона (трекер вышел 81 знак и не влезал).
- При расхождении со снимком лида не спорить рефлекторно, но и не переделывать сделанное: сначала перепроверить свои артефакты свежими командами.
