## Решения
- Health: игрок И враги — через `UStatsComponent` (TakeDamage БЕЗ Super). `HandleDeath()` virtual; `ReloadCurrentWeapon` virtual (патроны из рюкзака, AAmmoItem-стак).
- `GetMesh()==HeadMesh==Leader` модульного гуманоида; Torso/Legs — followers (SetLeaderPoseComponent). Оружие к кости `R_Hand`, офсеты — параметры.
- Волк — НЕ гуманоид: ACharacter + SK_Wolf + Single Node анимации; ИИ = AWolfAIController(AEnemyAIController).
- **SetFocus сам пешку НЕ вращает** (UE 5.5 Pawn.cpp:1049) — доворот наш StartAimTurnTo.
- ИИ погони: state-machine Idle/Chase/Attack, nav + direct-fallback; QA-лог дросселирован.
- **Сейв-слот один (`ContrarySave`), retention-поля в нём же (этап F):** `SaveGame()` игрока создаёт свежий объект → ПЕРЕНОСИТ retention-поля из прежнего сейва (`UContrarySaveGame::CopyRetentionData`), иначе автосейв костра обнулял бы серию/подсказки. Компоненты удержания правят ТОЛЬКО свои поля через `LoadOrCreateSaveObject`/`WriteSaveObject`. Игра при ЗАПУСКЕ сейв НЕ грузит (LoadGame только при смерти) → награда ежедневки зеркалится и в живые статы, и в `Save->Money`.
- Чистая логика серии ежедневки — `Retention/DailyRewardLogic.h` (DailyReward::Compute, без UObject) — гоняется headless-автотестом; перевод часов назад = награды нет, серия цела.

## Локализация: два урока по МЕТОДУ поиска (2026-07-20, после первого сбора переводов)
- **Обход по списку панелей структурно НЕ находит тексты, живущие в игровых классах** и попадающие на экран через геттер. Так выпали две дыры подряд: подписи меток над NPC (`ElderNPC.h`/`MasterTrader.h`, метод `IInteractableNPCInterface::GetNPCMarkerLabel`) и имя убийцы (`PlayerCharacter::LastDamagerName`). Правильный порядок обратный: СНАЧАЛА поиск по всему `Source` полей, чьё значение уходит игроку, ПОТОМ обход панелей.
- **Обратная проверка (половина урока от лида, сильнее моей):** искать слова в СОБРАННОМ файле перевода и смотреть, чего там НЕТ. Поиск по коду находит то, о чём догадался спросить; отсутствие записи в собранном файле показывает пропуск само, без гипотезы. Обе дыры всплыли именно так. Закреплено как шаг приёмки: после сбора взять список того, что игрок точно видит, и проверить каждое слово в файле.
- **Ловушка `FText::FromString` на потребителе:** обнуляет всю работу — текст становится culture-invariant и сборщик его не видит, даже если литерал объявлен через NSLOCTEXT. Была на экране смерти (`DeathScreenWidget.cpp:58`), убрана.
- Результат первого сбора (лид проверял сам): 170 текстов (107 из кода, 63 из ассетов), `Content/Localization/Game/ru/` на месте, служебные ключи `RequiredItemName`/`QuestLootItemName`/`QuestItemName` в манифест НЕ попали — разделение ключа и надписи сработало.
