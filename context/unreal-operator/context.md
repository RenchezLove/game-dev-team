## ⛔ Ловушки (каждая поймана живьём — не наступать снова)

- **Сверять имена и пути ассетов С КОДОМ ДО создания** — грепом по `Source/`, а не по письму лида. 07-28 письмо говорило `AM_MeleeSlash`, а код грузил `AM_Knife_Swing`; создай я по письму — фича молча умерла бы, а выглядело бы как «всё собралось». Расхождение доложить лиду и делать по коду, пока он не решит иначе. Мягкая ссылка на несуществующий ассет НЕ падает — она просто тихо не работает, поэтому такую ошибку не ловит ни сборка, ни тесты.
- **Отрицательный результат требует положительного контроля.** Прежде чем сказать «ссылок нет», в тот же прогон проверяю тем же методом заведомо ЖИВОЙ ассет и убеждаюсь, что список ссылок непустой. Иначе не отличить «ссылок нет» от «метод молча вернул пусто».
- **Поиск имени ловит имя-надстройку.** `MI_FogBand` как подстрока сидит внутри живого `MI_FogBandSoft`, `M_FogWall` — внутри `M_FogWall2`. Голый поиск даёт ложную «живую ссылку». Разводить: `grep -rao 'ИМЯ.\{0,4\}' | sort | uniq -c` — видно, чем продолжается каждое вхождение.
- **Grep-тул по ПАПКЕ с бинарями врёт.** ripgrep бросает бинарный файл на первом NUL-байте и отвечает «No files found» (BP_WorldBorder.uasset не нашёл сам себя). Бинарный поиск по папке — ТОЛЬКО `grep -rla` через Bash. По одному явному файлу Grep-тул ищет честно.
- **Реестр ассетов НЕ видит загрузку строкой-путём из C++** (`ConstructorHelpers`/`LoadObject`/`TSoftObjectPtr`): «0 референсеров» в реестре ≠ мёртвый ассет. Обязательно подтверждать грепом по `Source/` (искать и имя, и `/Game/...`-путь). Ловушка срабатывала на `SM_Pistol`.
- **`get_all_level_actors` НЕ ВИДИТ transient-акторы.** Полный список — `unreal.GameplayStatics.get_all_actors_of_class(world, unreal.Actor)` + фильтр + контрольный повтор листинга.
- **Созданный из Python подобъект (например уведомление в анимации) НАВСЕГДА блокирует удаление своего ассета в этом сеансе редактора.** Возвращённую обёртку держит питоновский учётчик ссылок движка: `obj refs name=<Ассет>` показывает цепочку `GCObjectReferencer → FPyReferenceCollector::AddReferencedObjects(<подобъект>) → Outer = <ассет>`. Не помогают ни `delete_asset`, ни `delete_loaded_asset`, ни `collect_garbage`, ни `gc.collect()`, ни закрытие редактора ассета, ни `TRANSACTION RESET` — все возвращают False при НУЛЕВЫХ внешних ссылках. Лечится перезапуском редактора либо удалением файла с диска. **Вывод: временные пробы делать в ОТДЕЛЬНОМ headless-процессе** — там та же уборка проходит с первого раза (проверено).
- **`delete_asset` в населённой папке исторически НЕнадёжен** (возвращал True, а файл оставался). Всегда проверять `os.path.exists` внутри того же скрипта и `ls`/`git status` снаружи.
- **Переименование ассета лучше заменять «удалить + создать заново» в свежем процессе** — не остаётся ни переходника-редиректора, ни старого имени внутри файла. Проверять: список редиректоров в папке пуст, листинг диска, и вытяжка строк из файла не содержит старого имени.
- **`get_referencers` СРАЗУ после операции в ТОМ ЖЕ процессе — устаревший.** Итоговую проверку делать в СВЕЖЕМ процессе после полного пересканирования.
- **In-memory ≠ диск.** Верификацию правки карты делать перезагрузкой (`load_map` заново после save), а не чтением того, что уже в памяти.
- **`set_collision_enabled()` на компоненте НЕ сериализуется** — на reload откат в дефолт из профиля. Записывается только `set_collision_profile_name("NoCollision"/"BlockAll")`.
- **Headless trace/sweep без PIE НЕВАЛИДЕН** — Chaos-сцена не инициализирована, возвращает канонический мусор. Коллизию проверять только в живом PIE.
- **`connect_material_expressions`: имя входного пина сопоставляется ПОСЛЕ сокращения** — «Input»→пустая строка, «Exponent»→«Exp», «Coordinates»→«UVs», «TextureObject»→«Tex», «MipLevel»→«Level», «MipBias»→«Bias», сравнения «A>B»/«A=B»/«A<B»; ВСЁ остальное (A, B, Alpha, Base, Min, Max, Value, X, Y) — как есть. Полный список — `UMaterialGraphNode::GetShortenPinName` в `Engine/Source/Editor/UnrealEd/Private/MaterialGraphNode.cpp`. При несовпадении connect ТИХО возвращает False → недосоединённый граф. Всегда проверять bool результата.
- **Спавн с `transient=True` карту всё равно ПОМЕЧАЕТ изменённой.** `bTransient` добавляет только флаг `RF_Transient` — актор не сериализуется, но пакет карты становится dirty, и снять флаг из Python НЕЧЕМ (`Package.set_dirty_flag` не экспонирован). Содержимое на диске не меняется (проверять md5 `.umap`). После теста уничтожить акторов и честно предупредить лида.
- **Поле `result` у `AssetImportTask` в 5.5 устарело и защищено** — чтение роняет скрипт УЖЕ ПОСЛЕ успешного импорта, выглядит как «импорт упал». Читать `imported_object_paths` или `get_objects()`.
- **Сокет на скелетном меше исчезает при смене меша, на скелете — нет.** Движок ищет сокет сначала в самом меше, потом в его скелете (`SkeletalMesh.cpp`, `FindSocketAndIndex`). В нашем модульном персонаже броня подменяет ассет меша слота (`MasterHumanoidCharacter.cpp:349`), в том числе меша-ЛИДЕРА головы, поэтому сокет надо класть на СКЕЛЕТ. Регистрация скелетов как совместимых сокеты НЕ разделяет. Python умеет `SkeletalMesh.add_socket`, но функций для сокетов СКЕЛЕТА не даёт вовсе. И главное: сокет НЕЛЬЗЯ называть именем кости — при совпадении сокет перекрывает кость (`GetSocketTransform`: сокет применяется первым).
- **Структуру анимационного блюпринта Python НЕ читает:** `EdGraph.Nodes` и `Skeleton.Sockets` protected, `BakedStateMachines` вообще не экспонировано. Рабочий метод — вытяжка печатных строк из `.uasset` (таблица имён) с обязательным положительным контролем. Кости и сокеты — через временный `unreal.SkeletalMeshComponent()` + `set_skeletal_mesh_asset` + `get_num_bones`/`get_bone_name`/`get_parent_bone`/`get_all_socket_names` (сокеты = то, что осталось после вычета костей). Позы костей — `Skeleton.get_reference_pose()` + `unreal.AnimPoseExtensions.get_bone_pose(поза, кость, WORLD)`.
- **Совместимость скелета и анимации движок проверяет ПО КОСТЯМ, а не по ассету** (`USkeleton::IsCompatibleMesh` сверяет имена и иерархию). Два разных ассета-скелета с одинаковым деревом костей работают вместе — не поднимать ложную тревогу.
- **Материал-инстансы:** поле `InitialParent` у фабрики в Python не экспонировано — родителя задавать `MaterialEditingLibrary.set_material_instance_parent(mi, parent)` ПОСЛЕ `create_asset`. **Баг UE 5.5:** `set_material_instance_scalar_parameter_value` применяет значение, но ВСЕГДА возвращает False — bool игнорировать, проверять обратным чтением.
- **Перевод в редакторе намеренно НЕ применяется** (`ILocalizedTextSource.h`, `ShouldLoadNativeGameData` при `GIsEditor` отдаёт родной язык). Проверять локализацию только в режиме игры: `-game -culture=<язык> -nullrhi -unattended -ExecCmds="Localization.DumpLiveTable -Key=<ключ>, quit"`, обязательно два прогона плюс контрольная непереведённая строка.
- **Прочие квирки UE 5.5 Python:** у WidgetBlueprint `WidgetTree`/`RootWidget` protected (брать `unreal.find_object(None, "/Game/UI/WBP_X.WBP_X:WidgetTree.<Имя>")`, обход — `get_children_count()`/`get_child_at(i)`); `unreal.Rotator(roll, pitch, yaw)` — надёжнее задавать присваиванием полей; кириллица в ASCII-логе UE превращается в мохибейк, значение проверять обратным чтением; кириллица в `.ps1` ломает парсер Windows PowerShell — строки скриптов писать латиницей.
- **GUI-автоматизация: рабочий стол может быть занят живым Ринатом.** Обязательный предохранитель перед каждым вводом: `GetForegroundWindow` → процесс должен быть UnrealEditor, иначе прервать всё. Дважды спасло от клика в чужое окно. Случайные скрины чужих окон удалять.
