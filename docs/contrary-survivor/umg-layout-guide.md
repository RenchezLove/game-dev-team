# Схемы раскладки UMG-виджетов (ADR-048)

Этот файл — инструкция для Рината: как собрать мышкой экраны интерфейса в редакторе.
Логика каждого экрана уже написана в C++; тебе нужно только разложить «кубики»
(кнопки, тексты, списки) так, как нравится визуально. Файл пополняется по мере
готовности C++-классов: сейчас здесь этап 1 — магазин.

## Как это устроено (один раз прочитать)

- Для каждого экрана есть C++-класс с логикой. Ты создаёшь на его основе **Widget
  Blueprint** (визуальный ассет, дальше «WBP») и раскладываешь в нём кубики.
- Код находит кубики **по точным именам**. Имя задаётся в редакторе виджета: выбери
  элемент в дереве слева (панель Hierarchy) и впиши имя в самом верху панели Details.
  Если имя не совпадёт с таблицей — кубик просто не заработает (в лог упадёт
  предупреждение, игра НЕ сломается).
- Класть можно НЕ все кубики сразу: чего нет — то не работает, остальное живёт.
  Можно собирать экран постепенно и сразу проверять в игре.
- Каждый WBP потом назначается в свой слот на `BP_ContrarySurvivorHUD` (категория
  **HUD | UMG Widgets** в Class Defaults). Пока слот пуст — работает старый экран,
  нарисованный кодом; назначил — включается твой WBP.

## ⚠️ Изменение от 2026-08-02 — «разлочка»: всё двигается мышкой

По твоей задаче все окна пересобраны так, что **каждый текст и каждая кнопка лежат
на канве** — свободном поле, где элемент можно выделить мышкой и просто перетащить;
у выделенного появляются квадратики-ручки по краям, ими меняется размер. Пунктирных
подложек-таблиц, которые запрещали двигать кубики по одному, больше нет: старые
горизонтальные и вертикальные ряды разобраны, их содержимое разложено по канве на
те же места, где оно стояло.

**Единственное общее правило: содержимое кнопки живёт внутри кнопки — двигается
кнопка целиком, а её подпись и иконка настраиваются внутри неё.** Начинка кнопок
специально «замкнута» (значок замка в панели Hierarchy), чтобы клик мышкой выделял
саму кнопку, а не подпись под курсором. Захочешь поправить текст или иконку внутри
кнопки — сними замок на её строке в Hierarchy, поправь и можешь вернуть замок
обратно.

Что где разлочено — помечено в разделах ниже пометкой «от 2026-08-02».

### Как создать WBP на нужном C++-классе

1. В Content Browser: правая кнопка → **User Interface → Widget Blueprint**.
2. В появившемся окне выбора родителя (Pick Parent Class) найди через поиск нужный
   C++-класс из таблицы ниже (например `ShopScreenWidget`) и выбери его.
   Если окно не появилось и виджет создался сразу — открой его, вверху меню
   **File → Reparent Blueprint** и выбери нужный класс там.
3. Назови ассет как в схеме (например `WBP_Shop`) и положи в `Content/UI/`.

## Этап 1 — Магазин

Нужно два ассета: `WBP_Shop` (сам экран) и `WBP_ShopRow` (одна строка списка —
товар или предмет рюкзака; код сам наплодит таких строк сколько нужно).

### WBP_Shop — экран магазина

- **Родительский класс:** `ShopScreenWidget`
- **Куда назначить готовый:** `BP_ContrarySurvivorHUD` → Class Defaults →
  категория **HUD | UMG Widgets** → поле **Shop Widget Class**.
- **Обязательная настройка внутри WBP_Shop:** открой Class Defaults самого WBP_Shop
  (кнопка Class Defaults на панели сверху), найди категорию **Shop** и в поле
  **Row Widget Class** выбери `WBP_ShopRow` (без этого списки будут пустыми).

Кубики (тип → точное имя → что делает):

**Изменение от 2026-07-20 (ADR-050, порция 1): подписи в магазине теперь твои.**
Как и в панели статов, код больше не пишет подписи — только значения. Слово «Монеты»
ты кладёшь отдельным обычным Text'ом с любым именем, а код ставит рядом только число.

**Изменение от 2026-08-02 (разлочка).** Контейнер `SliderQtyAmmoRow` больше не нужен
и в ассете его нет: строка пересчёта патронов — это один текст `SliderQtyAmmoText`,
он лежит прямо на канве панели количества, и код прячет/показывает его сам. Просто
двигай его мышкой как любой другой текст.

| Тип кубика | Точное имя | Что делает и где ему место |
|---|---|---|
| Text | `MoneyText` | Только ЧИСЛО монет игрока, например «150». Слово «Монеты» положи рядом отдельным Text'ом сам. Код обновляет число каждый кадр. Обычно — левый верх панели. |
| Scroll Box | `BuyList` | Список товаров торговца («FOR SALE»). Код сам наполняет его строками WBP_ShopRow. Прокрутка пальцем и колесом работает сама. Левая половина панели. |
| Scroll Box | `SellList` | Список предметов рюкзака на продажу. Тоже наполняется кодом. Правая половина панели. |
| Button | `CloseButton` | Закрыть магазин. Текст на кнопке (например «Close») напиши прямо в редакторе — положи внутрь кнопки обычный Text. Правый верхний угол. |

Панель количества (появляется при покупке/продаже стака; в остальное время код сам
её прячет). Собери эти кубики в отдельный контейнер — например Border или Vertical
Box поверх списков по центру:

| Тип кубика | Точное имя | Что делает |
|---|---|---|
| Любой контейнер (Border / Canvas Panel / Vertical Box) | `SliderPanel` | Корень панели количества. Код показывает/прячет ИМЕННО его — все кубики ниже клади ВНУТРЬ него. |
| Text | `SliderTitleText` | Заголовок «Купить: Бинт» / «Продать: Патроны 9мм». Ставит код целиком: слово «Купить» или «Продать» меняется по ходу сделки, поэтому в отдельную подпись его вынести нельзя. |
| Text | `SliderQtyText` | Только значение «3 из 10». Слово «Количество» положи рядом отдельным Text'ом сам. |
| Text | `SliderQtyAmmoText` | Строка пересчёта пачек в патроны: «всего 30 патронов». Ставит код; он же показывает её только при покупке патронов, в остальное время прячет. С 2026-08-02 лежит прямо на канве, обёртка-контейнер не нужна. |
| Slider | `QtySlider` | Ползунок количества. Диапазон и шаг код настраивает сам — в редакторе ничего в нём не меняй, только внешний вид. |
| Button | `QtyMinusButton` | Минус один. Подпись «−» положи внутрь кнопки сам. |
| Button | `QtyPlusButton` | Плюс один. Подпись «+» положи сам. |
| Text | `SliderTotalText` | Живая сумма: «Итого: 120» при покупке, «Выручка: +40» при продаже. Ставит код. |
| Button | `SliderConfirmButton` | Подтвердить сделку. Подпись (например «Confirm») положи сам. |
| Button | `SliderCancelButton` | Отменить. Подпись положи сам. |

Статичные надписи, которые код НЕ трогает (заголовки «TRADER», «FOR SALE (Купить)»,
«SELL FROM BACKPACK (Продать)») — добавляй обычными Text с любым именем и пиши в них
что хочешь: они целиком твои.

Настраиваемые форматы кода — Class Defaults WBP_Shop, категория **Shop | Texts**.
Текст в фигурных скобках код заменяет на число или название, остальное — твои слова.

| Настройка | По умолчанию | Что можно подставить |
|---|---|---|
| Money Format | `{Amount}` | `{Amount}` — монеты игрока. |
| Buy Action Text | `Купить` | подпись кнопки в списке товаров. |
| Sell Action Text | `Продать` | подпись кнопки в списке рюкзака. |
| Buy Price Format | `{Price}` | `{Price}` — цена покупки. |
| Sell Price Format | `+{Price}` | `{Price}` — сколько дадут за предмет. |
| Armor Bonus Format | `{ItemName} (+{Percent}% защиты)` | `{ItemName}` — название брони, `{Percent}` — прибавка защиты. |
| Buy Title Format | `Купить: {ItemName}` | `{ItemName}` — что покупаем. |
| Sell Title Format | `Продать: {ItemName}` | `{ItemName}` — что продаём. |
| Qty Format | `{Qty} из {Max}` | `{Qty}` — выбрано, `{Max}` — потолок. |
| Qty Ammo Format | `всего {Rounds} патронов` | `{Rounds}` — сколько патронов выйдет всего. |
| Total Format | `Итого: {Total}` | `{Total}` — сумма покупки. |
| Revenue Format | `Выручка: +{Total}` | `{Total}` — сумма выручки. |

### WBP_ShopRow — одна строка списка

- **Родительский класс:** `ShopRowWidget`
- **Куда назначить:** в поле **Row Widget Class** в Class Defaults `WBP_Shop`
  (см. выше). На HUD этот ассет назначать НЕ нужно.
- Это одна строка списка: имя, цена, кнопка. **С 2026-08-02 внутри плашки строки —
  канва `RowCanvas`:** имя растянуто от левого края и само переносится, цена и
  кнопка стоят у правого края, и всё это двигается мышкой по отдельности. Высоту
  строки задаёт корневой Size Box (сейчас 48 px; для пальца комфортно 40–60).

| Тип кубика | Точное имя | Что делает |
|---|---|---|
| Text | `NameText` | Название товара/предмета (у брони код допишет «(+15% защиты)»). Ставит код. |
| Text | `PriceText` | Цена: «120» в каталоге, «+40» в рюкзаке. Ставит код. Если этот кубик не положить — код допишет цену к названию, информация не потеряется. |
| Button | `ActionButton` | Кнопка действия строки. У недоступных к покупке товаров код сам гасит кнопку. |
| Text | `ActionText` | Подпись на кнопке («Купить»/«Продать» — ставит код). Положи этот Text ВНУТРЬ ActionButton. |
| Text | `NoMoneyText` | «Не хватает монет» — код показывает эту строку только в тех товарах, на которые не хватает денег, в остальных прячет. Раньше об этом говорил только цвет погашенной кнопки, а его часть игроков не считывает (требование ADR-049). Отдельной подписи рядом не нужно, это цельная фраза. Сейчас стоит левее цены: на канве спрятанный текст своё место не освобождает, поэтому у фразы своё постоянное место. |

Настраиваемые тексты строки — Class Defaults WBP_ShopRow, категория **ShopRow | Texts**:
`Name Price Format` (запасная склейка «{Name} — {Price}», когда нет кубика цены) и
`Not Enough Money Text` (сама фраза «Не хватает монет»).

### Как проверить магазин

1. Назначь `WBP_Shop` в слот Shop Widget Class на `BP_ContrarySurvivorHUD`.
2. Запусти игру, подойди к торговцу, нажми E (или кнопку ДЕЙСТВИЕ на телефоне).
3. Должны появиться твоя панель со списками. Купи что-нибудь со слайдером, продай
   предмет, закрой крестом и клавишей E. Если какой-то кубик не заработал — проверь
   его имя по таблице (лог пишет предупреждение с именем недостающего кубика).
4. Чтобы вернуть старый магазин — просто очисти слот Shop Widget Class.

## Этап 2 — Диалог старосты и инвентарь

### WBP_Dialog — окно разговора со старостой

- **Родительский класс:** `DialogScreenWidget`
- **Куда назначить:** `BP_ContrarySurvivorHUD` → **HUD | UMG Widgets** →
  поле **Dialog Widget Class**.
- Классическая нижняя панель «как в визуальных новеллах», но раскладка целиком твоя.
  Тексты реплик, как и раньше, настраиваются на самом старосте (BP_Elder, категория
  Dialog) и в его квестах — окно их только показывает.

| Тип кубика | Точное имя | Что делает |
|---|---|---|
| Text | `NPCNameText` | Имя собеседника («СТАРОСТА» — берётся с BP_Elder). Ставит код. |
| Text | `ReplicaText` | Сама реплика. ОБЯЗАТЕЛЬНО включи у него галочку **Auto Wrap Text** (панель Details → Wrapping) — длинные реплики переносятся на строки. Ставит код. |
| Button | `AcceptButton` | «Принять квест». Код сам показывает её только когда квест предлагается. Подпись «Принять» напиши внутри кнопки сам. |
| Button | `DeclineButton` | «Отказаться». Видна вместе с AcceptButton. Подпись напиши сам. |
| Button | `TurnInButton` | «Сдать квест» — видна, когда квест выполнен. Подпись ставит КОД (в ней сумма награды) — положи внутрь кнопки Text с именем `TurnInText`. |
| Text | `TurnInText` | Подпись кнопки сдачи «Сдать (+150)». Лежит ВНУТРИ TurnInButton. Ставит код. |
| Button | `CloseButton` | «Закрыть» — видна при взятом и при сданном квесте. Подпись напиши сам. |

⚠️ **Важное правило про подписи кнопок:** подпись клади ТОЛЬКО ВНУТРЬ кнопки. Код
прячет и показывает кнопки поштучно по состоянию квеста, и подпись внутри исчезает
вместе со своей кнопкой. Если положить её рядом с кнопкой, а не внутрь, она останется
висеть на экране в тех состояниях, где кнопки нет.

Кнопки, не подходящие текущему состоянию квеста, код прячет сам — клади все четыре
рядом (например в Horizontal Box внизу панели), лишние в каждый момент исчезнут.

**Изменение от 2026-07-20 (ADR-050, порция 2).** Квадратные скобки вокруг подписей
кнопок убраны: было «[ Принять ]», стало «Принять» — по требованию ADR-049, скобки
выглядели как временная затычка. Скобки вокруг награды в кнопке сдачи оставлены, они
показывают прибавку монет.

Настраиваемые форматы — Class Defaults WBP_Dialog, категория **Dialog | Texts**:

| Настройка | По умолчанию | Что можно подставить |
|---|---|---|
| Turn In Format | `Сдать (+{Reward})` | `{Reward}` — награда монетами. |
| Active Replica Format | `{Prefix}{Title} — {Objectives}.` | `{Prefix}` — начало фразы со старосты, `{Title}` — название квеста, `{Objectives}` — цели с прогрессом. |
| Objective Format | `{Objective} {Done} из {Total}` | `{Objective}` — что сделать, `{Done}` — сделано, `{Total}` — сколько надо. |
| Objective Separator | `, ` | вставляется между двумя целями, если их у квеста две. |
| Early Hook Separator | пробел | между описанием первого квеста и ранней фразой-намёком. |

Сами фразы старосты (имя, начало реплики о незаконченном квесте, реплики о выполненном
и сданном квесте, ранняя фраза-намёк) правятся не здесь, а на самом старосте:
выдели `BP_Elder` на уровне → Details → категория **Dialog**. Названия и описания всех
трёх квестов — там же, категория **Quest**.

### Строка статов вверху инвентаря (обновлено 2026-08-02)

Наверху панели живут три пары «иконка + значение»: монеты, голод, жажда. **С
2026-08-02 общего ряда-коробки у них больше нет** — все шесть кубиков лежат прямо
на канве панели, каждый двигается и настраивается мышкой по отдельности:

| Тип кубика | Точное имя | Что делает |
|---|---|---|
| Image | `InvMoneyIcon` | Иконка монеты. Чисто украшение — код её не трогает, можешь менять картинку, размер и место как хочешь. |
| Text | `InvMoneyText` | Только ЧИСЛО монет. Ставит код. |
| Image | `InvHungerIcon` | Иконка голода. Тоже целиком твоя. |
| Text | `InvHungerText` | Только значение голода, например «80 из 100». Ставит код. |
| Image | `InvThirstIcon` | Иконка жажды. Целиком твоя. |
| Text | `InvThirstText` | Только значение жажды. Ставит код. |

Одна особенность: числа в игре растут вправо. Если монет станет очень много
(четыре знака и больше), число может дотянуться до иконки голода — тогда просто
раздвинь пары мышкой пошире, теперь это делается за секунду.

Со слотом защиты и слотом оружия так же просто: рядом с `ProtectionText` лежит
слово **Защита**, рядом с `WeaponText` — слово **Оружие**; слова целиком твои,
код пишет только значения.

Статичные надписи («Инвентарь», «Снаряжение», «Рюкзак», подписи слотов брони, подсказка

### WBP_PlayerStats — постоянная панель статов (верх-лево)

- **Родительский класс:** `PlayerStatsWidget`
- **Куда назначить:** **Player Stats Widget Class**. Панель висит на экране всю игру.

**Важное изменение от 2026-07-20 (ADR-050): подписи теперь твои, код их не трогает.**
Раньше код каждый кадр писал в кубик всю строку целиком вместе с приставкой («HP 80/100»)
— поэтому текст, который ты вписывал в дизайнере, затирался в игре. Теперь подпись и
значение — это ДВА РАЗНЫХ кубика: подпись («Здоровье») ты кладёшь сам обычным Text'ом,
называешь как хочешь, пишешь и стилизуешь как хочешь — код её не ищет и не переписывает.
Код пишет только само число в кубик со специальным именем из таблицы ниже.

Кубики, которые код ищет по имени (только значения и полоски):

| Тип кубика | Точное имя | Что делает |
|---|---|---|
| Progress Bar | `HealthBar` | Полоска здоровья, заполнение ставит код. Цвета полоски — твои (Details → Appearance). |
| Text | `HealthText` | Значение «80/100». Ставит код. Удобно положить ПОВЕРХ полоски (Overlay). |
| Progress Bar | `HungerBar` | Полоска голода. |
| Text | `HungerText` | Значение «64». |
| Progress Bar | `ThirstBar` | Полоска жажды. |
| Text | `ThirstText` | Значение «71». |
| любой контейнер (Horizontal Box, Overlay, Border) | `AmmoRow` | Вся строка патронов ЦЕЛИКОМ: положи внутрь и свою подпись «Патроны», и значение. Код прячет этот контейнер, когда в руках нож или пустые руки — и подпись пропадает вместе с числом. Если такого контейнера нет, код спрячет только число, а твоя подпись «Патроны» останется висеть в воздухе. |
| Text | `AmmoText` | Значение «7 / 51» — в магазине и всего у игрока. Ставит код. |
| Text | `AmmoBagText` | НЕОБЯЗАТЕЛЬНЫЙ. Нужен, только если захочешь показать запас отдельной строкой со своей подписью. Формат у него свой (`Ammo Bag Format`). |
| Text | `MoneyText` | Значение «150». |

Подписи, которые кладёшь ТЫ (имена не важны, код их не видит): «Здоровье», «Голод»,
«Жажда», «Патроны», «Монеты» — обычные Text'ы рядом со значениями или внутри контейнера.

**Как настроить сам вид числа.** Class Defaults WBP_PlayerStats, категория
**PlayerStats | Texts**. Там лежат форматы: текст в фигурных скобках код заменяет на
число, всё остальное — твои слова. Например, формат здоровья по умолчанию `{Current}/{Max}`
даст «80/100»; напишешь `{Current} из {Max}` — получишь «80 из 100».

| Настройка | По умолчанию | Что можно подставить |
|---|---|---|
| Health Format | `{Current}/{Max}` | `{Current}` — здоровье сейчас, `{Max}` — максимум. |
| Hunger Format | `{Current}` | `{Current}` — голод сейчас, `{Max}` — максимум шкалы. |
| Thirst Format | `{Current}` | `{Current}` — жажда сейчас, `{Max}` — максимум шкалы. |
| Ammo Format | `{InClip} / {Total}` | `{InClip}` — патроны в магазине оружия, `{Total}` — сколько всего есть у игрока (запас при оружии плюс пачки в рюкзаке вместе). Именно это число игрок может расстрелять: перезарядка сама досыпает патроны из рюкзака. Отдельно доступны `{Reserve}` и `{Bag}`, если захочешь вернуть три числа. |
| Ammo Bag Format | `{Total}` | Те же подстановки, что и выше; используется, только если положил кубик `AmmoBagText`. |
| Money Format | `{Amount}` | `{Amount}` — сколько монет у игрока. |

### WBP_QuestTracker — строка квеста (верх-право)

- **Родительский класс:** `QuestTrackerWidget`
- **Куда назначить:** **Quest Tracker Widget Class**. Сам прячется без квеста и при
  открытых окнах.

| Тип кубика | Точное имя | Что делает |
|---|---|---|
| Text | `TrackerText` | «Квест: Собрать шкуры волков 1 из 3»; у выполненного — «Квест выполнен: Шкуры волков — вернись к старосте». Текст и цвет (золотой/зелёный) ставит код. Подложку-плашку под текстом сделай сам (Border). |

игры, поэтому в отдельную статичную подпись оно уйти не может.

Форматы и оба цвета — Class Defaults WBP_QuestTracker, категория **QuestTracker | Texts**:

| Настройка | По умолчанию | Что можно подставить |
|---|---|---|
| Tracker Format | `Квест: {Objectives}` | `{Objectives}` — цели с прогрессом. Название квеста в трекере НЕ показываем: на телефоне строка не влезала, а у первого квеста название и цель почти дублировали друг друга. Подставить `{Title}` при желании всё равно можно. |
| Done Format | `Квест выполнен: {Title} — вернись к старосте` | то же самое. У выполненного квеста прогресс не показываем: он и так «3 из 3», а строка длинная. |
| Objective Format | `{Objective} {Done} из {Total}` | `{Objective}` — что сделать, `{Done}` — сделано, `{Total}` — сколько надо. |
| Objective Separator | `, ` | вставляется между двумя целями, если их у квеста две. |

**Изменение от 2026-07-20 (ADR-050, порция 2).** Раньше в строке целей показывалось
служебное слово из настроек квеста, из-за чего во втором квесте игрок читал английское
«Bandit: 1/3» посреди русской строки. Теперь берётся человеческая подпись цели, которая
у квеста уже была заполнена («Перебить бандитов»), и строка читается «Перебить бандитов
1 из 3». Ту же строку целей показывает и реплика старосты — она собирается одним общим
кодом, так что формат в двух местах не разойдётся.

## Тач-слой геймплея — WBP_TouchControls (кнопки и стик на экране)

Это те кнопки, что видны ВО ВРЕМЯ игры: ОГОНЬ, ДЕЙСТВИЕ, СУМКА, ПЕРЕЗАРЯД, БЕГ,
ОРУЖИЕ, ПАУЗА и стик движения. Раньше они строились только кодом — теперь их можно
собрать в WBP и менять мышкой цвет, размер, шрифт и позицию каждой кнопки.

- **Родительский класс:** `TouchControlsWidget`
- **Куда назначить готовый:** НЕ на HUD, а на контроллер:
  `Content/System/BP_ContrarySurviorPlayerController` → Class Defaults → категория
  **Touch Controls → UMG Widgets** → поле **Touch Controls Widget Class**.
  Пока поле пустое — работает прежний слой, нарисованный кодом.
- Вся логика прежняя: держишь ОГОНЬ — автоогонь, БЕГ — переключатель, стик двигает
  персонажа. При открытом инвентаре/магазине боевые кнопки прячутся сами; СУМКА и
  ПАУЗА остаются.
- Чтобы слой был виден на ПК для проверки, на том же контроллере включи галочку
  **Enable Touch Controls** (категория Touch Controls).
- Важно: когда назначен WBP, настройки размеров/цветов кнопок на контроллере
  (поля Touch Fire Button и т.п.) больше НЕ действуют — всё берётся из твоего WBP.

| Тип кубика | Точное имя | Что делает |
|---|---|---|
| Image | `StickBase` | Подложка стика (большой круг). Где её поставишь и какого размера растянешь — там и будет стик: касание внутри неё начинает движение. |
| Image | `StickThumb` | «Шляпка» стика (малый круг под пальцем). Положи её ПОВЕРХ центра подложки — код сам двигает её за пальцем и возвращает на место. |
| Button | `FireButton` | ОГОНЬ: держать — автоогонь. |
| Text | `FireText` | Подпись внутри FireButton — текст пиши сам (например «ОГОНЬ»). |
| Button | `ReloadButton` | ПЕРЕЗАРЯД (как клавиша R). |
| Text | `ReloadText` | Подпись внутри ReloadButton. |
| Button | `InteractButton` | ДЕЙСТВИЕ (как клавиша E: подобрать/торговать/поговорить). |
| Text | `InteractText` | Подпись внутри InteractButton. |
| Button | `SprintButton` | БЕГ-переключатель: при включённом беге код подсвечивает кнопку жёлтым, при выключении возвращает твой цвет. |
| Text | `SprintText` | Подпись внутри SprintButton. |
| Button | `WeaponButton` | ОРУЖИЕ — смена пистолет/нож (как клавиша Q). |
| Text | `WeaponText` | Подпись внутри WeaponButton. |
| Button | `InventoryButton` | СУМКА — открыть/закрыть инвентарь (как Tab). Видна и при открытых окнах. |
| Text | `InventoryText` | Подпись внутри InventoryButton. |
| Button | `PauseButton` | ПАУЗА — меню паузы. Видна всегда. |
| Text | `PauseText` | Подпись внутри PauseButton. |

Советы: под палец комфортен диаметр кнопки 90–130 px; полупрозрачные цвета
(альфа 0.3–0.6) меньше заслоняют игру. Кубик, который не положишь, просто не
появится (в лог упадёт предупреждение с его именем) — можно начать с пары кнопок.

### Как проверить тач-слой

1. Назначь WBP_TouchControls в поле Touch Controls Widget Class контроллера и включи
   Enable Touch Controls.
2. Запусти игру: стик мышкой двигает персонажа, ОГОНЬ стреляет очередью пока зажат,
   БЕГ подсвечивается и ускоряет, СУМКА открывает инвентарь (боевые кнопки исчезают),
   повторный тап СУМКИ закрывает.
3. Вернуть кодовый слой — очисти поле Touch Controls Widget Class.
