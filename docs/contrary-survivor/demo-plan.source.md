## 1. Демо-петля (нарратив — утверждён Ринатом)
1. ГГ приходит в деревню (амнезия), ищет кров.
2. **Староста** (у костра) даёт квест: перебей стаю у **логова волков (ВОСТОК)**, принеси **3 шкуры**.
3. ГГ уничтожает стаю (**4 волка**), собирает **3 шкуры**, возвращается → **150 монет**.
4. Староста даёт квест на **базу бандитов (ЮГ)**: принеси **ноутбук** (зацепка «кто охотится за ГГ»).
5. ГГ зачищает базу (**3 бандита**), забирает **ноутбук (1)**, несёт старосте → **250 монет**.
6. Деньги тратятся у **торговца** (снаряжение, патроны, медикаменты, еда).

**Числа (утв.):** шкур 3, волков 4, бандитов 3, награды 150/250, ноут 1. Респаун: −40% денег + дроп расходников мешком (квест-предметы целы).

## 3. Архитектура интерфейсов (C++ ↔ BP) — для Этапа F

**Принцип (как Master-классы геймплея, ADR-024): логика — в C++ базовом виджете, визуал/вёрстка — в BP-наследнике (UMG).** C++ держит данные, делегаты и ссылки на элементы через `meta=(BindWidget)`; `WBP_*` рисуется/стилизуется в UMG — Ринат правит вид без кода.

| Экран | C++ база (логика) | BP-наследник (визуал, UMG) |
|---|---|---|
| HUD игрока | `UPlayerHUDWidget : UUserWidget` | `WBP_PlayerHUD` |
| Слот оружия (×2) | `UWeaponSlotWidget : UUserWidget` | `WBP_WeaponSlot` (огнестрел/холодное) |
| Инвентарь | `UInventoryWidget : UUserWidget` | `WBP_Inventory` |
| Ячейка инвентаря | `UInventorySlotWidget : UUserWidget` | `WBP_InventorySlot` (иконка+кол-во) |
| Магазин | `UShopWidget : UUserWidget` | `WBP_Shop` |
| Диалог NPC | `UDialogWidget : UUserWidget` | `WBP_Dialog` |
| Экран смерти | `UDeathScreenWidget : UUserWidget` | `WBP_DeathScreen` |

- **Создание/показ** виджетов — `APlayerController`/`AContrarySurvivorHUD` (`CreateWidget`, видимость). Старый Canvas-рендер удаляется (F8).
- **Данные** — виджеты читают `UStatsComponent`/`UInventoryComponent`/`UQuestComponent` и подписываются на делегаты (обновление по событию, дёшево для Android).
- **Иконки предметов** — поле в `DT_Items` (E2) → инвентарь и слоты оружия берут оттуда.
- **Слоты оружия** — 2 фиксированных (огнестрел + холодное) в HUD, связаны с экипировкой игрока.

## 4. Ключевые решения (свод; ADR — `docs/decisions.md`)
- **ADR-023** /Content feature-first · **ADR-024** BP-наследники C++, базы `AMasterEnemyBase` · **ADR-025** `IShopVendor` · **ADR-026** NPC-гуманоиды · **ADR-027** модель смерти/респауна · **ADR-028** команда делает инструменты, расстановку — Ринат; базы = один BP · **ADR-029** `NumToSpawn` · **ADR-030** облегчённый гейт.
- **Дальность отрисовки — НЕ делаем** (06-26): убрали ручной cull; для top-down достаточно встроенного frustum culling.
- **Камера LDoE — настраивается в BP** игрока.
- **Холодное оружие — радиусный урон** (06-26): отменяет «урон по цели под прицелом»; бьёт всех в радиусе, радиус визуализируется, удар размашистый. → ADR при реализации (D).
- **Реорганизация карты/деревни** (06-26): центр-дом → костёр+лавка+пропсы; логово ВОСТОК, база ЮГ, карта крупнее. → ADR при утверждении схем.
- **Архитектура UI на UMG** (06-26): C++ база + BP-визуал. → ADR при старте Этапа F.

## 5. Порядок и зависимости
```
✅ 0 → ✅ A → ✅ B
        ↓
⏳ C (реорг карты/деревни: схемы → пропсы → расстановка → дороги → переезд баз)
        ↓
⏳ D (оружие: визуал + радиусный урон холодного)
        ↓
⏳ E (DataTable; иконки предметов нужны для F) ──┐
        ↓                                        │ иконки
⏳ F (интерфейс UMG: HUD/слоты/инвентарь-иконки/магазин/диалоги) ◄┘
        ↓
⏳ G (прогон → Android → стабилизация)
```
Логика: реорг карты (C) первым — на неё ложатся дороги и вид. Оружие (D) — играбельность. DataTable (E) даёт иконки предметов для инвентаря-иконок (F) → E перед F (каркас UMG F1–F2 можно параллелить). Финал (G) — последним.

## 6. Параметры тюнинга
- Числа демки: шкур 3, волков 4, бандитов 3, награды 150/250, ноут 1.
